## 動手之前：三個關於 ARGO 的事實

這三件事決定了整套自動化長什麼樣子，先看懂會省下很多摸索。

### ① ARGO 的畫面是 Java（Oracle Forms），不是一般 Windows 程式

`ArgoERP.exe` 只有 1MB，它是個**啟動器**。真正的畫面來自同目錄下的
`frmsal.jar`（Oracle Forms Standalone Application Launcher），由 Java 跑起來。

**所以**：自動化要找的視窗屬於 **java/javaw 程序**，不是 `ArgoERP.exe`。
實測 `ArgoERP.exe` 的視窗標題是空的，拿它當目標一定抓不到。

### ② 閒置 15 分鐘自動斷線

排程在 17:40 跑的時候，ARGO 一定早就斷了。所以腳本必須**自己完整登入**，
不能假設視窗開著。

副作用：斷線後 `ArgoERP.exe` 不會自己結束。掃描當下就看到三個殘留程序
（9/16、9/18、9/21 啟動的，都沒有視窗）。腳本啟動前會先清掉這些。

### ③ 傳簽沒有 API，只能按畫面

2026-09-24 向 ARGO 廠商確認，三個答案都是不行：

1. `IFAF105` 不支援更新既有請購單的 `HOLD_STATUS`（UNSIGNED → SIGNING）
2. 沒有專門的「傳簽」介面
3. 傳簽文號／傳簽類別不能由 API 帶入

我們自己唯讀查 `PJ_APPLYPROJECT` 也印證了——傳簽實際改了三個欄位：

| 欄位 | 未傳簽 | 已傳簽 |
| --- | --- | --- |
| `HOLD_STATUS` | `UNSIGNED` | `SIGNING` |
| `SIGN_FLAG` | `null` | `Y` |
| `PFM_DOCUMENT_NO` | `null` | `PBM260924019` |

關鍵在 `PFM_DOCUMENT_NO`：傳簽真正做的事是**在簽核模組另外產生一張 PBM 文件**。
就算能改 `HOLD_STATUS`，沒有那張文件，簽核流程還是不會跑。

> 註：查 `PFM_*` 表會回「WebService 未授權」，但實測打一個**根本不存在的表名也回同一句**，
> 所以不能拿它當「開了權限就能做」的依據。

## 步驟 1：設定環境變數（3 分鐘）

開 PowerShell（一般權限即可），貼上執行：

```powershell
[Environment]::SetEnvironmentVariable('ARGO_SIGN_BASE_URL', 'https://bardshop-eip.vercel.app', 'User')
[Environment]::SetEnvironmentVariable('ARGO_SIGN_SECRET',   '<這裡填下面產出的那把鑰匙>', 'User')
[Environment]::SetEnvironmentVariable('ARGO_SIGN_EXE',      'C:\Users\USER\AppData\Local\ArgoERP\ArgoERP.exe', 'User')
```

`ARGO_SIGN_SECRET` 是**這支腳本專屬**的鑰匙，要自己產一把、在 Vercel 和本機各設一次。

為什麼不共用 `WEBHOOK_SECRET`：
- **最小權限**：這把只開得了「讀待傳簽清單／查單張狀態」，觸發不了任何排程端點。
  腳本跑在辦公室的個人電腦上，萬一外流，損害範圍差很多。
- **實務上也拿不到**：Vercel 把 `WEBHOOK_SECRET` 設成 Sensitive，存進去就讀不出來，
  「Copy to Clipboard」是灰的，只能覆寫不能看。去改它還會連帶影響其他在用的排程。

產鑰匙（在 PowerShell 打）：

```powershell
[Convert]::ToBase64String((1..24 | ForEach-Object { Get-Random -Max 256 })) -replace '\+','-' -replace '/','_' -replace '='
```

把產出的字串**同時**設到兩個地方：
1. Vercel → 專案 → Settings → Environment Variables → Add New，
   Key 填 `ARGO_SIGN_SECRET`，Value 貼字串，Environment 勾 **Production**，存檔後**重新部署**
2. 本機（下面的第三行指令）

設完**關掉這個 PowerShell 視窗再重開**，新視窗才讀得到。驗證：

```powershell
$env:ARGO_SIGN_BASE_URL   # 應該印出網址
$env:ARGO_SIGN_EXE        # 應該印出 ArgoERP.exe 路徑
```

**關於 ARGO 帳密**：不用設，腳本也不接受。實測確認 ARGO 登入畫面的「Remember me」
會把帳密帶好，腳本只要送 `Tab×3` + `Enter` 就登得進去。所以密碼不進腳本、
不進環境變數、不進 git——這不是省事，是刻意不把 ERP 密碼放到這台電腦的
環境變數裡（那裡任何程式都讀得到，而且不會留下讀取紀錄）。

如果哪天 Remember me 失效，正確的處理是**進 ARGO 重新勾一次**，不是把密碼寫進腳本。

## 步驟 2：Java Access Bridge —— 結果不用裝

原本以為要靠它才看得到 Java 畫面裡的按鈕。**實測之後確認不需要**，這一步可以跳過：

- ARGO 的 Java 表單（登入、主選單、請購作業）**全程只用鍵盤**就走得完：
  `Tab` / `Enter` / `F7` / `F8`，還可以直接打程式代號 `PJAF084` 跳到作業畫面。
  Oracle Forms 對鍵盤的支援本來就完整，不需要「看見」按鈕。
- 唯一需要滑鼠的是啟動器上的 `BARDSHOP` 按鈕，但啟動器是 **WinForms（.NET）**
  不是 Java，用內建的 UI Automation 就找得到它，跟 Access Bridge 無關。

留著這段是因為「不需要」本身就是有用的結論——省下裝 32 位元 JRE 跟重開機，
也少一個會壞的相依。真的哪天要讀 Java 子視窗的內容才需要回來裝它。

## 步驟 3：視窗結構（已實測，列在這裡供日後對照）

腳本靠視窗標題判斷「現在走到哪一步」。2026-09-24 用 `capture-argo-ui.ps1` 實測結果：

| 畫面 | 程序 | 頂層視窗標題 |
| --- | --- | --- |
| 啟動器 | `ArgoERP` | `ArgoERP` |
| 登入畫面 | `java` | 有標題但不含公司別 |
| 登入完成後 | `java` | `啟盛國際股份有限公司(BARDSHOP):10149@BARDSHOP 2026/09/24 18:47 上線人數:5` |

**兩個限制寫進腳本裡了，改腳本前一定要知道**：

1. 登入後的標題含**即時時間與上線人數**，每分鐘都在變。只能用萬用字元
   （`*BARDSHOP*`）比對，寫死整串明天就失效。
2. ARGO 是 **MDI**：登入畫面、主選單、原物料請購作業都是同一個 java 頂層視窗
   裡的**子視窗**。子視窗標題（`原物料請購作業–PJAF084 v4.23`）在
   `EnumWindows` / `MainWindowTitle` 裡**看不到**。
   所以靠標題只能判斷「登入了沒」，**判斷不出現在停在哪個作業畫面**——
   這就是為什麼每張單按完都要回頭向 ARGO 驗證狀態，那是唯一可靠的確認。

日後 ARGO 改版要重新確認時：

```powershell
cd C:\Users\USER\factory-scheduler\scripts\argo-sign
.\capture-argo-ui.ps1 -Watch      # 唯讀，不會點任何東西
```

## 步驟 5：按鍵序列（已校準完成）

全部由現場操作人員實測提供，腳本裡照著實作，**沒有猜測的部分**：

| 階段 | 動作 |
| --- | --- |
| 啟動器 | **滑鼠**點 `BARDSHOP`（只能滑鼠，見下） |
| 登入畫面 | 等約 4 秒讓資料讀出來 → `Tab×3` → `Enter`（帳密由 Remember me 帶入） |
| 主選單 | 直接打 `PJAF084` → `Enter`，進原物料請購作業 |
| 每張單 | `F7` 進查詢 → 貼上單號 → `F8` 查詢 → 等 2.5 秒 → `Tab×15` → `Enter` 按傳簽 |

**為什麼公司別按鈕只能用滑鼠**：它是 WinForms 按鈕，但 UI Automation 把它歸類成
`Pane` 而且**不支援任何 pattern**——沒有 `InvokePattern` 可以直接觸發，鍵盤也走不到。

但腳本**沒有寫死座標**。中心點是執行當下用 UI Automation 依按鈕文字查出來的，
所以視窗被移動、換解析度、按鈕排列調整都還是點得到。寫死座標的版本明天換個螢幕
就會靜默點空——那正是這支腳本最要避免的失敗模式。

### 先做一次「只登入不傳簽」的演練

這很重要：登入流程如果第一次執行是明天 17:40 的無人值守排程，壞了也沒人看到。
所以先在**有人看著畫面**的時候跑這個，它會登入、開好請購作業，然後停下，
**不按任何傳簽**：

```powershell
cd C:\Users\USER\factory-scheduler\scripts\argo-sign
.\argo-sign.ps1 -LoginOnly -KeepOpen
```

畫面應該停在「原物料請購作業」。停在別的地方就是某一步的等待時間不夠，
用 `-LoginWaitMs 6000` 或 `-FormWaitMs 6000` 加長再試。

### 真正跑一次

確認登入沒問題後，等到有待傳簽的單時跑（沒有單它會直接結束，不會亂按）：

```powershell
.\argo-sign.ps1 -KeepOpen
```

`-KeepOpen` 讓 ARGO 跑完不關，方便對照畫面。每張單按完腳本都會回頭問 ARGO
狀態有沒有變成 `SIGNING`，**沒變就立刻停**，不會繼續空按下一張。

## 步驟 6：設排程

Windows 工作排程器，建議 **17:40**——兩輪自動轉單（17:10／17:35）都跑完之後、
伺服器端 17:50 檢查之前。這樣腳本失敗時，17:50 那道防線還來得及發現。

以**系統管理員**開 PowerShell：

```powershell
$act = New-ScheduledTaskAction -Execute 'powershell.exe' `
  -Argument '-NoProfile -ExecutionPolicy Bypass -File "C:\Users\USER\factory-scheduler\scripts\argo-sign\argo-sign.ps1"'
$trg = New-ScheduledTaskTrigger -Daily -At 17:40
Register-ScheduledTask -TaskName 'ARGO請購單自動傳簽' -Action $act -Trigger $trg -RunLevel Highest
```

**必看**：工作排程器要設成「**只在使用者登入時執行**」。UI 自動化需要互動式桌面，
勾「不論使用者是否登入」會讓腳本在看不見的工作階段裡跑，什麼都按不到，而且失敗得很安靜。

## 這套為什麼這樣設計：每按一張就驗一張

桌面自動化的失敗幾乎都是**靜默**的——視窗沒開、欄位沒對焦、按鈕位置跑掉，
腳本照樣跑完並回報成功。**沒有驗證的自動化比沒有自動化更危險**，因為不會有人發現。

```
系統告訴腳本「今天該按哪幾張」 → 按一張 → 立刻回查 ARGO 狀態
                                   ↑              │
                                   └── 有變才繼續 ─┘
                                       沒變就停 + 記 log + 回非 0
```

而且伺服器端還有一道**獨立**防線：每天 17:50 的 `pr-sign-check` 會自己查一次，
還有沒傳簽的就發 LINE。**就算本機腳本整個沒跑、電腦關機，你也會知道。**

伺服器端端點：

| 端點 | 用途 |
| --- | --- |
| `GET /api/argoerp/pending-sign` | 今天待傳簽的單號 |
| `GET /api/argoerp/pending-sign?verify=單號` | 查單張現在的狀態 |
| `GET /api/argoerp/pending-sign?date=YYYY-MM-DD` | 指定日期補查 |
| `/api/cron/pr-sign-check`（每天 17:50） | 獨立防線，沒傳簽就發 LINE |

## 已知限制

- 腳本一遇到驗證失敗就**停**，不繼續處理後面的單。這是故意的：同一個 UI 問題通常會
  讓後面每一張都失敗，繼續按只是把錯誤放大。
- 單量大到單次處理超過 15 分鐘而中途斷線時，逐張驗證會抓到（狀態沒變就停），
  不會默默跳過後面的單。
- ARGO 改版或畫面調整後，視窗標題與按鍵可能要重新校準。log 會直接告訴你卡在哪一張、
  當時狀態是什麼。
- log 在 `scripts\argo-sign\logs\argo-sign-YYYYMMDD.log`。

# ARGO 請購單自動傳簽 — 設定指引

2026-09-24

## 這件事為什麼不能純 API 解決

ARGO 的請購單開出來是 `UNSIGNED`，要人進 ARGO 桌面程式按「傳簽」才會進入簽核流程。
2026-09-24 向 ARGO 廠商確認過三件事，答案都是不行：

1. `IFAF105` 不支援更新既有請購單的 `HOLD_STATUS`（UNSIGNED → SIGNING）
2. 沒有專門的「傳簽」介面
3. 傳簽文號／傳簽類別不能由 API 帶入

我們自己也查證過（唯讀查 `PJ_APPLYPROJECT`），傳簽實際上改了三個欄位：

| 欄位 | 未傳簽 | 已傳簽 |
| --- | --- | --- |
| `HOLD_STATUS` | `UNSIGNED` | `SIGNING` |
| `SIGN_FLAG` | `null` | `Y` |
| `PFM_DOCUMENT_NO` | `null` | `PBM260924019` |

關鍵在 `PFM_DOCUMENT_NO`：傳簽真正做的事是**在簽核模組另外產生一張 PBM 文件**，
不是改欄位就算數。所以就算能改 `HOLD_STATUS`，沒有那張文件，簽核流程還是不會跑。

> 註：查 `PFM_*` 相關表會回「WebService 未授權」，但實測打一個**根本不存在的表名也回同一句**，
> 所以那個訊息無法證明那些表存在。不要拿它當作「只要開權限就能做」的依據。

**結論：傳簽只能在本機用 UI 自動化按。**

## 整套的設計原則：每按一張就驗一張

桌面自動化的失敗幾乎都是**靜默**的——視窗沒開、欄位沒對焦、按鈕位置跑掉，
腳本照樣跑完並回報成功。沒有驗證的自動化比沒有自動化更危險，因為你不會發現。

所以這套的骨架是：

```
系統告訴腳本「今天該按哪幾張」  →  腳本按一張  →  立刻回查 ARGO 狀態
                                      ↑                    │
                                      └──── 有變才繼續 ────┘
                                            沒變就停 + 記 log + 回非 0
```

另外伺服器端還有一道獨立的防線：每天 17:50 的 `pr-sign-check` 排程會自己查一次，
還有沒傳簽的就發 LINE。**就算本機腳本整個沒跑，你也會知道。**

## 一、伺服器端（已完成）

| 端點 | 用途 |
| --- | --- |
| `GET /api/argoerp/pending-sign` | 今天待傳簽的單號清單 |
| `GET /api/argoerp/pending-sign?verify=單號` | 查單張現在的狀態（腳本按完用這個驗證） |
| `GET /api/argoerp/pending-sign?date=YYYY-MM-DD` | 指定日期補查 |
| `/api/cron/pr-sign-check`（每天 17:50） | 獨立防線，沒傳簽就發 LINE |

認證用 `Authorization: Bearer <WEBHOOK_SECRET>`。

先用瀏覽器登入後開 `/api/argoerp/pending-sign` 確認回得出東西，再往下做。

## 二、本機腳本

檔案：`scripts/argo-sign/argo-sign.ps1`

### 設定環境變數（一次性）

以系統管理員開 PowerShell：

```powershell
[Environment]::SetEnvironmentVariable('ARGO_SIGN_BASE_URL', 'https://bardshop-eip.vercel.app', 'User')
[Environment]::SetEnvironmentVariable('ARGO_SIGN_SECRET', '<WEBHOOK_SECRET 的值>', 'User')
```

### 先跑 DryRun 確認接得通

```powershell
cd <repo>\scripts\argo-sign
.\argo-sign.ps1 -DryRun
```

應該會列出今天開的單號與各自狀態。這一步**完全不碰 ARGO**，可以安心跑。

### 校準 UI 操作（唯一需要你動手的部分）

腳本裡 `Sign-OneDoc` 函式有一段標著 `▼▼▼ 校準區 ▼▼▼`，裡面是四個步驟的按鍵序列。
預設值是猜的，一定要在你的機器上實際校準一次：

1. 手動開 ARGO →「原物料請購作業」
2. 手動做一次完整的「查詢單號 → 按傳簽」，把每一步用到的**鍵盤**操作記下來
3. 把記下來的按鍵替換進校準區

**為什麼用鍵盤而不是滑鼠座標**：座標會因為視窗位置、螢幕解析度、顯示縮放比例而跑掉，
換一台電腦或把視窗拖動一下就壞。鍵盤序列跟著焦點走，穩定得多。

ARGO 是 Oracle Forms，大多數操作都有鍵盤對應（查詢多半是 `F7` 進入查詢模式、`F8` 執行）。
如果「傳簽」按鈕沒有快捷鍵，改用 UI Automation 依按鈕名稱點擊——這時要先啟用
**Java Access Bridge**（命令列跑 `jabswitch -enable` 後重開機），否則自動化工具看不到
Java 視窗裡的元件，只能退回座標點擊。

確認 ARGO 是不是 Java：工作管理員看處理程序是不是 `javaw.exe`，或安裝目錄底下有沒有 `jre`。

### 正式跑

```powershell
.\argo-sign.ps1
```

log 會寫在 `scripts\argo-sign\logs\argo-sign-YYYYMMDD.log`。

## 三、排程

Windows 工作排程器，建議 **17:40**（兩輪自動轉單 17:10／17:35 都跑完之後、
伺服器端 17:50 檢查之前——這樣腳本失敗時 17:50 那道防線還來得及發現）。

```powershell
$act = New-ScheduledTaskAction -Execute 'powershell.exe' `
  -Argument '-NoProfile -ExecutionPolicy Bypass -File "<repo>\scripts\argo-sign\argo-sign.ps1"'
$trg = New-ScheduledTaskTrigger -Daily -At 17:40
Register-ScheduledTask -TaskName 'ARGO請購單自動傳簽' -Action $act -Trigger $trg -RunLevel Highest
```

**重要**：工作排程器要設成「只在使用者登入時執行」。UI 自動化需要有互動式桌面，
勾「不論使用者是否登入」會讓腳本在看不見的工作階段裡跑，按不到任何東西。

## 四、已知限制

- **ARGO 必須事先開著並停在「原物料請購作業」**。腳本刻意不負責登入——登入畫面最容易
  卡住（密碼過期、公司別選錯、連線逾時），自動化處理這些只會製造更難查的失敗。
- 腳本一遇到驗證失敗就停，不會繼續處理後面的單。這是故意的：同一個 UI 問題通常會
  讓後面每一張都失敗，繼續按只是把錯誤放大。
- ARGO 改版或畫面調整後，校準區要重新校準。log 會直接告訴你是哪一張、卡在什麼狀態。

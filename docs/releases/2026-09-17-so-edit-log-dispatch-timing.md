# 訂單修改紀錄：發單前／發單後改判時間依據 (2026-09-17)

## 本次更新重點

> 「訂單修改紀錄」分頁原本判斷「已發單後才改」的方式是錯的：它看的是這張單
> **現在**有沒有製令與發單上傳紀錄，而不是「這筆修改發生時發過單了沒」。
> 於是一張 9/7 修改、9/14 才發單的訂單，會被標成「發單後才改」而驚動現場
> （實例：SO260907029、SO260910023）；反過來，發單很久以後才改、但製令
> 對不上行號的單，又會被標成「未發單」而漏通知。
>
> 修正後，發單時間一律以**每日出單表（daily_order_sheets）裡這張單第一次
> 出現的日期**為準，逐筆比較「修改時間 vs 實際發單日」：
> - 修改在發單日之前 → 標「發單前改」（發出的工單已是新內容，通知美編即可）
> - 修改在發單日之後 → 才是真正的「發單後改」，照舊點名已動工的站
> - 同一天因出單表沒有時刻、分不出先後 → 從嚴視為發單後（寧可多通知）
>
> 以近 3 天實際資料試算：1,388 筆變更中 152 筆從「發單後」修正為「發單前」
> （原本的誤報），73 筆從「發單前」修正為「發單後」（原本的漏報）。

## 介面變化

- 「發單狀態」欄新增該單的實際發單日（如 `2026-09-14 發單`）；
  出單表查無但狀態顯示有下游紀錄時，改標「出單表查無」提醒矛盾。
- 修改發生在發單日之前時，狀態旁加綠色「發單前改」標籤——
  即使這張單現在已在生產中，也不會再被誤讀成發單後才改。
- 「⚠ 只看已發單後才改」篩選與統計改用新判定。
- CSV 匯出新增「發單日」「發單前後」兩欄。
- 判讀說明補上「發單狀態＝現況；發單前後＝時間比較」的區分。

## 技術

- `app/api/argoerp/so-edit-log/route.ts`
  - 新增 `loadDispatchDates()`：全表掃 `daily_order_sheets`（sheet_date 升冪、
    分頁讀到底），取每張單第一次出現的 `sheet_date` 當實際發單日。
  - `EditLogEntry` 新增 `dispatchDate`、`editedAfterDispatch`；
    `notifyTarget()` 與新增／刪除品項的通知判定改吃 `editedAfterDispatch`，
    不再使用「現況五級狀態 ≥ 已發單上傳」。
  - 「發單狀態」五級（未發單→生產中）保留原樣，仍是現況資訊；
    只有「發單前／後」的判定換成時間比較。
- `app/admin/argoerp/erp-sync/SoEditLogCard.tsx`：篩選、統計、顯示、CSV 同步跟進。

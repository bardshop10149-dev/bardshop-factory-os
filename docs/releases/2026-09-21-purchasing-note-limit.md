# 採購專區：備註字數上限放寬並顯示剩餘字數 (2026-09-21)

## 本次更新重點

> Snow 回報「後面備註的字數好像有限制，導致一些文字被卡掉」。
>
> 查下來根因是追蹤列表備註輸入格的 `maxLength={500}`：**HTML textarea 的 maxLength 是「靜默」擋字的**
> ——打到上限後畫面毫無反應，游標照樣閃、也沒有任何提示，使用者只會覺得「後面的字被系統吃掉」。
> 因為當下就發現不對、沒有存檔，資料庫裡反而找不到 500 字的紀錄（實查 3,138 筆備註，最長僅 212 字），
> 這也是為什麼從資料面看不出異常。
>
> 調整三點：
> 1. 上限 500 → **2000 字**（前端與 API 同步放寬；DB 欄位本來就是 text 無上限）。
> 2. 剩餘 100 字內開始在輸入格右下角顯示「剩 N 字」（到頂顯示紅字「已達上限」），
>    限制不再無聲無息。
> 3. 自動長高上限 240px → **420px**，長備註不必拖拉就看得完。

## 技術

- `app/purchasing/page.tsx`：新增 `NOTE_MAX_LEN = 2000`，NoteCell 外層改包 `relative` 容器
  以放置計數器；自動長高上限提高到 420px。
- `app/api/purchasing/status/route.ts`：`NOTE_MAX_LEN` 500 → 2000。
  **兩處必須一起改**——只放寬前端的話，超過 500 字會在儲存時被 API 回 400。

## 驗證

- `npx tsc --noEmit` 0 errors。
- 實查線上資料：`po_line_tracking` 有備註 3,138 筆，最長 212 字、無任何一筆達舊上限，
  確認放寬不影響既有資料；DB 欄位為 `text`，無需 migration。

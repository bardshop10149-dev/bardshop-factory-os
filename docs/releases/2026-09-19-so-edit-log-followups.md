# 訂單修改紀錄：前置單號正名、常平委外單不再誤標未發單、表頭固定 (2026-09-19)

## 本次更新重點

> 依 Snow 的三項回饋調整：
>
> **1. 「客戶單號」正名為「前置單號」**
> 修改位置欄的 `tpn_part_no` 標籤原本寫「客戶單號」，實際語意是前置單號（打樣單號），改回正確名稱。
>
> **2. 有發單日卻顯示「未發單」的矛盾修正**
> 發單狀態的「未發單」其實是「ERP 查不到這張單的任何製令」。但**常平廠與委外單不開 MOT 製令**
> （走採購單），所以永遠查無製令、狀態永遠掛「未發單」——即使出單表明明已經發單了。
> 修正後：出單表有發單日但 ERP 無製令時，狀態顯示<span>已發單</span>（琥珀色），
> 滑鼠移上去說明「常平／委外單不開製令屬正常」。出單表也查無的單才維持「未發單」。
> 以近 3 天實際資料試算：102 張改到的訂單中，**19 張（124 筆變更列）**從「未發單」修正為「已發單」；
> 另 60 張真正未發單的維持原樣。
>
> 附帶說明：這些列「應通知」顯示全廠並非誤判——它們改的是**交期**，
> 而交期一動整條排程要重排，依現行規則本來就通知全廠，與發單狀態無關。
>
> **3. 表頭固定**
> 往下捲動時表頭會跟著，不會忘記欄位代表什麼。

## 技術

- `app/api/argoerp/so-edit-log/route.ts`
  - `FIELD_LABEL.tpn_part_no`：客戶單號 → 前置單號。
  - 組 entry 時，`dispatchState === '未發單'` 但有 `dispatchDate` → 改為 `'已發單'`。
    判定寫在 API 層而非前端，CSV 匯出與其他使用端才會一致。
- `app/admin/argoerp/erp-sync/SoEditLogCard.tsx`
  - 新增「已發單」的 `STATE_STYLE`（琥珀）與 `STATE_RANK`（2，與已開製令同級）。
  - 表頭改為 `sticky top-0` + 自帶底色；**sticky 貼在 `th` 上**（貼 thead/tr 在部分瀏覽器不生效）。
  - 表格容器從 `overflow-x-auto` 改為 `max-h-[75vh] overflow-auto`：
    容器要在垂直方向可捲動，sticky 才有作用；單純改 `overflow-x-clip` 雖然也能固定表頭，
    但窄畫面會把右側欄位裁掉且捲不回來。
  - 判讀說明補上「已發單」的意義。

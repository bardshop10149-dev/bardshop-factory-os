# 商品開發：新品項編碼申請（可引用類似品項帶入 ERP 設定）

發布日期：2026-09-10
範圍：首頁「商品開發」專區、新頁面 `/product-dev/item-request`。權限沿用既有的「商品開發（product_dev）」。

---

## 一句話

商品開發要開新的品項編碼，不用再靠口頭或訊息交代：在 EIP 填一張申請單，還可以「引用」一個性質最接近的既有品項，把它在 ARGO 的整組設定原封不動複製過來，建檔人員照單抄進 ARGO 就好。

## 公告欄白話版

> 🆕 **商品開發：申請新品項編碼**
> 首頁 →「商品開發」→ **申請新品項編碼**
>
> 1. **先搜尋一個類似的既有品項**（打編碼前幾碼或品名關鍵字），按「引用」
>    → 單位、產品大類/次類別、庫存類型、預設倉、會計科目全部自動帶進來
> 2. 把**品項名稱、規格**改成新品項的，確認 ERP 設定
> 3. 填**用途說明**（要用在哪張單、為什麼現有編碼不能用），送出
> 4. 建檔人員在 ARGO 建好後，回「申請進度」填入實際編碼 → 狀態變成「已建檔」
>
> 沒有類似品項可引用時，選完產品大類可以按「套用此類常見設定」當起點。
> 會計科目、庫存類型這些欄位**不確定就別改**，沿用引用來源最安全。

---

## 為什麼做「引用」而不是讓人自己填

ARGO 料件主檔（`MM_BOM_PART`）有 295 個欄位。實際抽查 1,336 筆現有品項後，人真正要決定的只有六、七個（品名、規格、單位、大類、次類別、安全庫存），其餘幾乎完全由「這是哪一類料」決定：

| 大類 | 用途 | 庫存類型 | 成本類別 | 存貨科目 | 預設倉 | 批號控管 | 費用類 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| M | 材料 | M | M | 1148 / 1315 | FS100 | 否 | 否 |
| W | 耗材、輔料 | M | M_MRO | 1148 / 1316 | FS100 | 否 | 否 |
| P | 自製成品 | FINSHED_GOODS | FINSHED_GOODS | 1143 / 1311 | FS100 | 是 | 否 |
| C | 採購成品 | P | P | 1141 / 1301 | FS100 | 是 | 否 |
| S | 費用（加工／服務） | P | P | 515 / 5736 | FEXP | 否 | 是 |
| A | 費用（其他） | P | P | 62 / 6288 | FEXP | 否 | 是 |
| O | 委外 | FINSHED_GOODS | FINSHED_GOODS | 1143 / 1311 | （空） | 否 | 否 |

這張表是**統計出來的常見值，不是規則**——例外真的存在（例如 S 類的存貨科目就有 5736 / 5714 / 5111 / 1311 四種）。所以表單的預設值只當備援，主要途徑是「引用一筆真實品項」：複製的是那一筆當下在 ARGO 的實際值，永遠不會因為規則整理過時而填錯。

## 資料怎麼流

```
商開填表 ──POST──▶ /api/product-dev/item-request ──▶ Supabase item_code_requests（狀態 pending）
   ▲                                                          │
   │ 引用帶入                                                   │ 建檔人員在 ARGO（IFAF007 / BOMF027）建立編碼
   │                                                          ▼
/api/product-dev/part-lookup ──即時查──▶ ARGO MM_BOM_PART      回填實際編碼 ──PATCH──▶ 狀態 created
```

**EIP 不會寫入 ARGO。** 品項編碼仍由建檔人員在 ARGO 手動建立，EIP 只負責「申請 → 追蹤 → 結案」。這是刻意的：料件主檔一旦建錯，牽動會計科目與所有後續單據，不適合讓表單直接寫進去。

引用時是**即時查 ARGO**，不走 Supabase 同步表。EIP 目前只同步了 `mm_bom_part_units`（料號→單位），要複製會計科目就得回頭查真值；為此多開一條同步排程，只會多一個會過期的資料源。

## 新增檔案

| 檔案 | 作用 |
| --- | --- |
| `sql/20260910_item_code_requests.sql` | 申請單資料表（欄位名對齊 ARGO，建檔可逐欄照抄） |
| `lib/productDev/argoParts.ts` | 查 ARGO 料件主檔（唯讀），含 filter 字串淨化 |
| `app/api/product-dev/part-lookup/route.ts` | 搜尋既有品項 / 取單筆完整設定 |
| `app/api/product-dev/item-request/route.ts` | 申請單 GET / POST / PATCH |
| `app/product-dev/item-request/page.tsx` | 申請表單＋申請進度 |

既有檔案只動 `app/page.tsx` 一處：商品開發彈窗多一顆「申請新品項編碼」按鈕。

## 安全

- 三支 API 全部 `guardPermission('product_dev')`，資料表只開 `service_role` policy，前端不直連。
- 申請人、申請單號、狀態一律由後端寫入，前端送什麼都不採用。
- ARGO 的查詢條件會被原樣拼進 Oracle 的 WHERE 子句，等同注入點：送進去前先移除引號、跳脫字元、LIKE 萬用字元與控制字元，料號另外限制成英數與 `- _ .`。

## 上線待辦

2. 確認要使用的同事已有「商品開發」權限（後台 → 團隊管理）
3. 生產環境需有 `ARGOERP_API_BASE` / `ARGOERP_USERNAME` / `ARGOERP_PASSWORD` / `ARGOERP_SEGMENT`（採購與 ERP 同步已在用，通常已存在）

# 修正：已完工的製令不再顯示成「未開始」

發布日期：2026-08-19
範圍：每日出單表 → 點製令號跳出的製程視窗。

---

## 問題

有些單在別的系統顯示「此張單已結束」，但在 EIP 點製令進去，各站卻寫「未開工」。
實例：`MOT26080402501`（PACRS-422ME3-KZ，數量 3）。

## 原因

塔台**結案後會把該批從清單移除**。EIP 查不到就退回資料庫的標準途程＋報工快照，
而快照裡沒有報工紀錄 → 每一站都被判成「未開工」。

也就是說：**「查不到報工」被當成「還沒做」，但實際上是「紀錄已經不在了」。**
同樣的誤判也會發生在常平／委外不報工的單上。

## 修法

新增「製令是否已完工繳庫」這個獨立訊號，不再只靠報工推論。

- 新 `lib/argoQuery.ts`：ARGO `S_QUERY` 的最小封裝（原本的呼叫全埋在
  `app/api/argoerp/route.ts` 內部，route 檔不能被 import），並提供 `fetchMoReceipt()`
  查 `PJ_PROJECTDETAIL` 的 `ORDER_QTY` / `ACTUAL_QTY`。
- `mo-route` API 每次回應都帶 `receipt`（完工/部分/未繳庫）。查詢與塔台平行發車，不增加等待。
- 視窗最上方新增**繳庫橫幅**：`已完工繳庫 3 / 3`，標題列同步出現「✅ 已完工」。
- 當「已完工 + 只有備援快照」時：各站狀態從「未開工」改為「**無現場紀錄**」，
  並明說下表是標準途程、不代表實際報工。

### 為什麼一定要即時問 ARGO

EIP 的 `erp_mo_lines` 只同步 `order_qty`，**沒有 `actual_qty`**；
`hold_status` 也不是完工旗標（已完工的單照樣是 `OPEN`，全表 3,668 筆只有 8 筆 `CLOSE`）。
本地資料庫查不出「做完了沒」，唯一可靠來源是 ARGO 繳庫數。

## 驗證（打正式站 ARGO 實測）

| 製令 | ARGO 繳庫 | 判定 | 塔台 | 相符 |
|---|---|---|---|---|
| `MOT26080402501` | 3 / 3 | `completed` | 查無（已結案移除） | ✅ 與「此張單已結束」一致 |
| `MOT26080651214` | 0 / 2 | `none` | 進行中 67%，3 站報工 2/2、2/2、0/2 | ✅ 確實還沒做完 |

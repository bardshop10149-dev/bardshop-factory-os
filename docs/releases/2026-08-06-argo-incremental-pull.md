# ARGO 同步改「增量拉」＋ 每 5 分鐘排程（第三階段）

發布日期：2026-08-06
範圍：`app/api/argoerp/route.ts`（各同步 action 新增增量查詢分支）、`lib/erpSyncReconcile.ts`（引擎新增增量模式）、新增 `app/api/cron/sync` 排程端點。**按鈕行為、回傳格式、頁面完全不變。**

---

## 一句話

同步從「每次把整張表從 ARGO 整包撈回來」改成「只撈這幾分鐘真的有異動的那幾筆」，資料新鮮度從 25～57 分鐘提升到 **5 分鐘**，而總負載跟現在持平甚至更輕。

## 為什麼可行（2026-08-06 對正式 ARGO 實測）

| 查詢 | 筆數 | 耗時 |
|---|---|---|
| 表身 `PJ_PROJECTDETAIL` **全量**（原本做法） | 40,244 | 3,583ms |
| 表身 **近 5 分鐘增量** | 1 | 79ms |
| 表身 近 1 小時 | 2 | 78ms |

- 確認 `UPDATE_DATE` **表頭與表身都有**，且**粒度到秒**（`2026/08/04 11:03:04`），5 分鐘窗口完全可行。
- 實測整輪增量（SO+MO+PO+PR+客戶）**1.5 秒**跑完；同一輪全量需 45～74 秒。

## 設計要點

- **不存浮水印**：直接用 ARGO 自己的 `SYSDATE - INTERVAL '20' MINUTE` 當窗口。免除時鐘誤差問題，且 20 分鐘窗口對 5 分鐘排程＝4 倍重疊緩衝，某輪失敗或部署重啟都能自動補回。
- **增量絕不刪除**：引擎新增 `mode: 'incremental'`——「這輪沒拉到」只代表沒異動，不代表被刪。刪除偵測交給每天 4 次全量對帳。
- **只讀受影響單**：增量模式下比對既有列時用 `scopeIds` 限縮，不再每輪把整張大表讀出來。
- **表頭改 → 連該單所有表身重抓**：否則表身列裡的表頭欄位（客戶/狀態/地址）不會更新。
- **大批異動自動退回全量**：受影響單號超過 300 張時改跑全量（更划算，也避開 Oracle IN 上限）。
- **產出保證一致**：只在「查 ARGO」那段加過濾條件，中間組資料的程式碼完全共用，因此增量與全量寫出的列一模一樣，不會互相覆蓋。實測連跑兩輪第二輪為 0 寫入（冪等）。

## 各單別對應

| 同步 | 增量支援 | 說明 |
|---|---|---|
| SO / MO / PO | ✅ 完整增量 | 表頭＋表身雙窗口取聯集，重抓受影響單 |
| PR 請購 | ✅ 閘門式 | 查詢有多段 fallback、聯表加 IN 易觸發 ORA-00918；全量本身很輕（4 千筆/0.8 秒），故僅用窗口判斷「有無異動」，有異動才跑完整流程 |
| 客戶 | ✅ 完整增量 | 單表直接過濾 |
| **庫存** | ❌ 只能全量 | `MM_BOM_BOH_V` 是 view，**沒有 `UPDATE_DATE`** |
| **批備料** | ❌ 只能全量 | 無可靠自然鍵、寫入為整批覆蓋，無法只寫部分列 |
| BOM 單位／結構 | ❌ 走全量 | 量小且為 upsert，放 30 分鐘那批即可（順帶解決 BOM 單位長期未更新） |

## 順帶修掉的既有 bug

`sync_so` 表頭查詢未取 `INVOICE_FORMAT` / `CUSTOMER_REMARK`，導致**每次同步都把發票型態、訂單備註覆寫成 null**，並產生數千筆「假變動」——這正是全量同步耗時被拉長、變更紀錄被污染的原因。已補上欄位（實測 `PJ_PROJECT` 確有這兩欄）。修正後實測：一次性回填 5,081 筆，之後穩定為 **0 變動**。

## 排程設定（cron-job.org，共 3 個工作）

全部打同一支端點，Header `Authorization: Bearer <WEBHOOK_SECRET>`：

| 工作 | 網址 | 排程 |
|---|---|---|
| 增量 | `POST /api/cron/sync?mode=incremental` | 每 5 分鐘，09:00–19:00 |
| 庫存/備料/BOM | `POST /api/cron/sync?mode=heavy` | 每 30 分鐘 |
| 全量對帳 | `POST /api/cron/sync?mode=full` | 每天 08:00 / 13:00 / 19:00 / 01:00 |

**保險**：若 `mode=full` 在正式站接近函式時間上限，可不改程式、改拆兩個工作：
`?mode=full&group=orders`（訂單類）與 `?mode=full&group=master`（主檔類），錯開幾分鐘即可。

> 原有的按鈕與舊排程完全不受影響；要回退只要把這 3 個 cron 工作停用，即恢復原本行為。

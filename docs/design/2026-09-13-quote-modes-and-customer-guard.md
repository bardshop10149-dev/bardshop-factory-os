# 報價計算機：三種檢視模式與客戶版（VIP）防蒸餾設計

> 日期：2026-09-13　狀態：工程／業務模式已實作；客戶版為設計稿，待 Snow 拍板後實作。
> 相關：`docs/design/2026-09-13-quote-cost-model.md`、`docs/design/2026-09-13-quote-ui-spec.md`

## 0. 一句話

**成本不是「前端藏起來」，是伺服器根本不回。** 三種模式是三個不同的 API 回應形狀，
誰能拿到哪一種由伺服器看權限決定；前端傳的 `mode` 只是「請求」，不是「授權」。

## 1. 三種模式

| 模式 | 誰能用 | 伺服器回什麼 | 包裝／覆寫 | 狀態 |
|---|---|---|---|---|
| `engineer` 工程 | `quote_admin`（或 admin） | 五段明細、算式、成本單價、毛利、成本率、每盤／盤數、拼板、價格快照 | 全部可調（包裝勾選、每箱件數、每盤覆寫、t1/t2/t3、報廢率……） | ✅ 已實作 |
| `sales` 業務 | `info_board` | **只有** `quoteUnit`、`total`、`twdUnit`、`warnings` | 包裝一律用品項預設，覆寫一律不收 | ✅ 已實作（預設模式） |
| `customer` 客戶 VIP | 之後另開權限／帳號類型 | 同 sales 再減：無 warnings 細節、無費率版本、無有效期以外的中繼資料 | 同 sales；尺寸／數量格點化（見 §3） | 🔜 設計稿 |

### 1.1 伺服器閘門在哪

`lib/quote/data.ts` → `runCalc()`：

```
canEngineer = member.isAdmin || member.permissions.includes('quote_admin')
mode        = body.mode === 'engineer' && canEngineer ? 'engineer' : 'sales'
```

- 非 engineer：每款結果只組 `{ id, quoteUnit, total, twdUnit, warnings }`——**不是把成本設 0，是根本沒有那個 key**。
  `priceSnapshot` 整個 `delete`；`ENGINE` 類警告（會透露拼板結果）也濾掉。
- 非 engineer：`sizes[].nOverride`、`overrides`、`packing` 一律丟棄，包裝改用 `product.config.packing` 裡 `defaultOn !== false` 的項目。
- `/api/quote/log`（產生報價）用 `runCalc(..., { audit: true })`：**計算規則照模式走**（業務仍是預設包裝），
  但落庫存完整五段與價格快照給稽核；回給前端的只有報價編號與摘要。

### 1.2 前端怎麼配合

- `catalog.canEngineer` 為 true 才畫「業務／工程」切換鈕（頁首右側）；本地記 `q.mode`，但沒權限時記了也沒用。
- 面板：非工程模式不畫每盤／盤數／覆寫／成本明細／毛利；中段一行「※ 包裝與工序已依品項預設計入；此為業務模式，不顯示成本明細」。
- 區段四：包裝清單改成唯讀一行「已包含：OPP 袋、紙箱……」——業務知道有什麼，不用挑、也看不到單價。
- 摘要（可貼 LINE 的文字）在業務模式沒有「每盤數量」那行。

**為什麼不做成前端開關就好**：DevTools → Network 一眼就看到 JSON。前端藏只防老實人。

## 2. 客戶版（VIP）的威脅模型

對象：同行拿到 VIP 帳號（或 VIP 客戶把帳號借給同行），想**用大量查詢反推我們的成本結構**——
不是偷一個價，是「蒸餾」：跑幾百組尺寸×數量，回歸出板價、印刷費、固定費攤提、成本率。

一個 8×10.2 的鑰匙圈 5,000 / 21,000 / 50,000 三個價，配一個會算的人，就能反推出「固定製版費 ≈ X、每件變動成本 ≈ Y、加價率 ≈ Z」。
所以防護重點不是「藏數字」，是**降低每次查詢帶出的資訊量、限制查詢次數、留下可追的痕跡**。

## 3. 防護設計（建議全做；每條獨立可關）

### 3.1 回應瘦身（資訊量）
- 只回 `quoteUnit`（兩位小數）、`total`、有效期。**不回** twd 匯率明細、費率版本、warnings 原文、產品版本。
- 拼板失敗只回「此尺寸無法報價，請聯絡業務」，不說「超過 29×39 可用範圍」（那句等於公布套版尺寸）。

### 3.2 參數格點化（讓回歸沒有連續資料）
- 尺寸只能選格點：0.5 cm 一格（或品項設定的尺寸清單）；數量只能選階梯：500 / 1,000 / 2,000 / 3,000 / 5,000 / 10,000（品項可設）。
- 板材厚度只給品項允許的 2～3 種；印刷方式只給「單面／雙面」，方法由品項預設決定（客戶不需要知道 7151 vs 柯式）。
- 效果：同行拿不到「5,001 vs 5,000」這種差分，固定費攤提曲線的採樣點只有 6 個。

### 3.3 按鈕計算、不即時
- 業務版是 150 ms debounce 即時算；客戶版改「填完按『取得報價』才算」，一次一筆，並套 3.4 的配額。
- 即時算等於免費的無限查詢，跟配額互相矛盾。

### 3.4 配額與速率限制（帳號 + IP 兩層）
- 每帳號：每日 N 次成功報價（建議 20）、每分鐘 5 次；每 IP：每日 60 次（多帳號共用 IP 也擋）。
- 超額回 429 + 「今日報價次數已達上限，請聯絡業務」，**同時通知業務**（LINE bot 既有 push 可用）。
- 實作：`quote_customer_usage(account_id, ip, day, count)` 一張表 + upsert；不用 Redis，量很小。

### 3.5 每筆都留痕（可追、可證）
- 客戶版每次查詢寫 `quote_calc_logs`，多存 `ip`、`user_agent`、`account_id`、`fingerprint`（可選）。
- 報價編號用獨立前綴 `QC-YYYYMMDD-NN`，跟內部 `Q-` 分開；報價文字上印帳號名稱與編號（水印效果：截圖外流查得到是誰）。

### 3.6 異常偵測（事後）
- 每日排程掃客戶版 log：同帳號一天內 >N 種不同尺寸、數量階梯全掃一遍、多帳號同 IP、深夜密集查詢 → 標記並寄信（走既有 07:30 日報那套）。
- 這是「知道被蒸餾了」的手段，配合 3.4 才有意義。

### 3.7 明確不做
- **不做價格擾動**（隨機 ±1%）：客戶拿到的報價會跟業務手上的對不起來，信任損失遠大於防護效果。
- 不做「客戶版用另一套簡化公式」：兩套公式會漂移，最後又要對帳。客戶版就是 sales 模式的子集。
- 不靠 CAPTCHA 擋——VIP 客戶體驗優先，配額比驗證碼有效。

## 4. 實作順序建議

1. 型別已預留：`QuoteMode = 'engineer' | 'sales' | 'customer'`；`runCalc` 的閘門加第三段即可。
2. 帳號：客戶版**不走 EIP 員工帳號**，另開 `quote_customer_accounts`（VIP 客戶對應業務、啟用／停用、配額）。
3. 路由：`/quote/c/[token]` 或獨立子網域，layout 不載 EIP 導覽；權限 guard 另寫，不混進 `guardQuote`。
4. 先上 3.1～3.5，跑一個月看 log 再決定 3.6 的閾值。

## 5. 給工程師的提醒

- `CalcSizeResult` 裡成本欄位全是 optional：**任何新 UI 都用 `size.costUnit != null` 判斷**，不能假設一定有。
- 新增成本相關欄位時，記得同時加進 `runCalc` 的剝除清單（現在是「非 engineer 只挑白名單欄位」，所以新欄位預設是被剝掉的——這是刻意的 fail-closed）。
- 客戶版的錯誤訊息要另寫一份，不能重用內部的（內部訊息會提到板材規格、拼板、每盤）。
